# My Tree CCU

Веб-трекер деревьев, посаженных студентами колледжа в рамках инициативы «Таза Казахстан». Он ведёт общий каталог посадок, план ухода и журнал изменений. Frontend — HTML/CSS/Vanilla JavaScript; API работает как локальный Node.js сервер или Vercel serverless-функция, а постоянное хранилище — PostgreSQL.

> Каталог новой базы пуст. Норма CO₂ — условная оценка, а оранжевые точки карты — предложения для проверки, не подтверждённые места посадки.

## Возможности

- Общий каталог деревьев с поиском по названию и по тому, кто посадил дерево, и фильтром по статусу.
- Интерактивная карта Колледжа Каспийского Университета (ККУ), Сейфуллина, 521, с точкой кампуса и условными кандидатами для осмотра.
- Добавление посадки: название, студент или группа, дата и начальный статус.
- Статусы ухода: `Посажено`, `Полито`, `Прижилось`.
- Журнал добавления деревьев и смены статусов.
- Аккаунты с ролями администратора, редактора и просмотра.
- PostgreSQL-хранение посадок, аккаунтов, сессий и истории, сохраняющееся после перезапуска и между serverless-вызовами.
- Редактирование и подтверждаемое удаление посадки, заметки об уходе и дата следующего полива.
- Адаптивный интерфейс для компьютера и телефона.

## Требования

- Node.js 24 или новее для локального сервера и утилиты миграции.
- PostgreSQL 14 или новее и строка подключения `DATABASE_URL`.
- npm, который устанавливается вместе с Node.js.
- Драйвер PostgreSQL `pg`, устанавливаемый через `npm install`.

Проверить версии:

```powershell
node --version
npm --version
```

## Запуск

Откройте PowerShell в папке проекта и выполните:

```powershell
npm install
Copy-Item .env.example .env
npm start
```

В `.env` укажите URI подключения из Supabase: откройте **Connect**, выберите **Transaction pooler** и скопируйте URI в `DATABASE_URL`. Если пароль содержит специальные символы, используйте URI-кодированное значение, указанное Supabase. Файл `.env` исключён из Git. Не отправляйте URL в чат и не коммитьте его. Для Vercel задайте то же значение как secret environment variable `DATABASE_URL`.

Откройте сайт: <http://127.0.0.1:3000>.

Для разработки с автоматическим перезапуском Node.js после изменения серверного кода:

```powershell
npm run dev
```

Остановить сервер: нажать `Ctrl+C` в том же окне PowerShell. Пока сервер остановлен, сайт и API недоступны.

Если порт `3000` занят, задайте другой порт перед запуском:

```powershell
$env:PORT = '3001'
npm start
```

Тогда сайт будет на <http://127.0.0.1:3001>. Переменная действует в текущем окне PowerShell.

## Первый запуск и вход

1. Запустите сервер и откройте сайт.
2. Если в активной базе нет аккаунтов, появится форма первичной настройки. Создайте администратора.
3. После этого открытая регистрация отключается; остальные аккаунты создаёт администратор.
4. Если импортирована старая база с аккаунтом, форма настройки не появится — войдите по прежним реквизитам.

**Логин:** 3–32 символа, латинские буквы, цифры, точка, дефис или подчёркивание. Пробелы и кириллица не допускаются; логин сохраняется в нижнем регистре.

**Пароль:** 10–128 символов. При первичной настройке пароль и повтор должны совпасть. Вводите пароль только в форме сайта, не отправляйте его в чат и не сохраняйте в README.

Сессии хранятся в PostgreSQL, поэтому перезапуск приложения или другой serverless-инстанс не завершает вход. Срок сессии — 8 часов.

## Роли и доступ

| Роль | Просмотр каталога | Добавление | Смена статуса | Аккаунты |
| --- | --- | --- | --- | --- |
| Гость | Да | Нет | Нет | Нет |
| Только просмотр (`viewer`) | Да | Нет | Нет | Нет |
| Редактор (`editor`) | Да | Да | Да | Нет |
| Администратор (`admin`) | Да | Да | Да | Да |

Администратор создаёт аккаунты `editor` и `viewer`, задаёт начальный пароль и передаёт его человеку отдельно. Отзыв аккаунта завершает его активные сессии. Удаление аккаунта не удаляет ранее созданные деревья и события. Удалить текущий аккаунт администратора через интерфейс нельзя.

Изменить роль аккаунта нельзя: отзовите доступ и создайте пользователя заново с нужной ролью.

## Работа с каталогом

- **Добавить или изменить посадку:** заполните название, «Кем посажено», дату, статус, заметку об уходе и следующий полив. Название — до 48 символов, участник/группа — до 32 символов, заметка — до 1000; дата посадки не позднее сегодняшнего дня.
- **Удалить посадку:** редактор или администратор подтверждает удаление. Событие остаётся в журнале.
- **Найти дерево:** введите часть названия или имени/группы в строку поиска.
- **Отфильтровать:** выберите статус или «Все статусы».
- **Отметить уход:** редактор или администратор меняет статус прямо в строке дерева.
- **Посмотреть журнал:** интерфейс показывает до 8 последних событий, сервер хранит до 100.

Обязательные поля проверяются и браузером, и сервером.

### Как считаются показатели

- Количество деревьев — число записей в каталоге.
- Участники — количество уникальных значений поля «Кем посажено» без учёта регистра и крайних пробелов. Различные написания считаются разными участниками.
- «Деревьев на контроле» — деревья со статусом `Посажено` или `Полито`; `Прижилось` исключается.
- «Прижилось» — доля деревьев со статусом `Прижилось`, округлённая до целого процента.
- CO₂ — оценка по формуле `число посадок × 22 кг на дерево в год`. Это не подтверждённые измерения; возраст, порода и дата посадки не учитываются.
- Прогресс сопоставляется с демонстрационной целью `2 000 кг`. Коэффициент и цель заданы в `index.html`, через интерфейс не меняются.

Замените демонстрационные записи и коэффициент CO₂ на проверенные данные и согласованную формулу перед использованием статистики в отчёте.

### Карта кампуса

Карта центрируется по адресу ККУ **Алматы, проспект Сейфуллина, 521** (ориентир: `43.256802, 76.932054`). Зелёная метка обозначает кампус, оранжевые A/B/C — только демонстрационные предложения для осмотра рядом с адресом. Они не подтверждают, что в этих местах разрешена или технически возможна посадка. Перед реальной посадкой проверьте территорию, коммуникации и получите разрешение администрации колледжа.

Карта построена на Leaflet и тайлах OpenStreetMap с обязательной атрибуцией на самой карте. Для её отображения браузеру нужен интернет и доступ к `unpkg.com` и `tile.openstreetmap.org`. Если библиотека карты не загрузится, трекер покажет сообщение вместо интерактивной карты; каталог и API продолжат работать.

## Данные и резервное копирование

При первом запросе API сервер создаёт таблицы `trees`, `activity`, `users`, `sessions` и `login_attempts` в PostgreSQL. Нужна переменная `DATABASE_URL`; локальный SQLite и память процесса для API не используются. Без доступной базы API возвращает ошибку конфигурации или соединения, данные не подменяются демо-записями.

Чтобы перенести базу старой версии, задайте `DATABASE_URL` и выполните `npm run migrate:sqlite`. По умолчанию читается `data/my-tree-ccu.sqlite`; исходный файл можно выбрать переменной `MYTREE_DATABASE_FILE`. Миграция переносит посадки, журнал и хеши аккаунтов транзакционно, остановится, если целевая база не пуста, и не удаляет SQLite. После переноса проверьте количество записей и вход.

Создать резервную копию:

```powershell
pg_dump --format=custom --file=my-tree-ccu.backup "$env:DATABASE_URL"
```

Восстановить в пустую базу:

```powershell
pg_restore --no-owner --dbname="$env:DATABASE_URL" my-tree-ccu.backup
```

Храните копии отдельно от репозитория, ограничьте к ним доступ и регулярно проверяйте восстановление. Для production дополнительно включите snapshots/PITR у провайдера PostgreSQL. Не публикуйте дампы, `.env`, пароли или значения секретов в GitHub.

## HTTP API

API обслуживается тем же Node.js сервером. JSON-запросы отправляются с `Content-Type: application/json`. При входе сервер устанавливает cookie сессии, которую браузер отправляет автоматически. Изменяющие запросы проверяют источник, когда заголовок `Origin` присутствует.

| Метод и путь | Доступ | Назначение |
| --- | --- | --- |
| `GET /api/health` | Публичный | Проверка сервера, ответ `{ "ok": true }`. |
| `GET /api/auth/me` | Публичный | Текущий пользователь и флаг `setupRequired`. |
| `POST /api/auth/setup` | Пока нет аккаунтов | Создать первого администратора и войти. |
| `POST /api/auth/login` | Публичный | Войти по логину и паролю. |
| `POST /api/auth/logout` | Сессия | Завершить текущую сессию. |
| `GET /api/users` | Администратор | Список аккаунтов без парольных полей. |
| `POST /api/users` | Администратор | Создать `editor` или `viewer`. |
| `DELETE /api/users/:id` | Администратор | Отозвать доступ другого пользователя. |
| `GET /api/trees` | Публичный | Получить `{ trees, activity }`; секреты пользователей не включаются. |
| `POST /api/trees` | Редактор, администратор | Добавить посадку и событие журнала. |
| `PATCH /api/trees/:id` | Редактор, администратор | Изменить поля посадки и ухода. |
| `DELETE /api/trees/:id` | Редактор, администратор | Удалить посадку после подтверждения в интерфейсе и добавить событие журнала. |
| `PATCH /api/trees/:id/status` | Редактор, администратор | Изменить статус и добавить событие. |

Пример тела для `POST /api/trees`:

```json
{
	"name": "Дуб «CCU-5»",
	"plantedBy": "Э-21",
	"date": "2026-10-11",
	"status": "planted",
	"careNotes": "Проверить мульчу",
	"nextWateringOn": "2026-10-15"
}
```

Допустимые статусы: `planted`, `watered`, `established`. Для создания аккаунта передаются `username`, `password`, `role` (`editor` или `viewer`). Для изменения статуса тело содержит `{"status":"watered"}`.

Типичные ответы: `400` — ошибка проверки данных; `401` — нет действующей сессии; `403` — не хватает прав или источник запроса не разрешён; `404` — маршрут/дерево не найдено; `409` — конфликт первичной настройки или логина; `413` — JSON больше 16 КБ; `429` — превышен лимит входа (10 попыток за 15 минут с IP).

## Ограничения и безопасность

- Локальный сервер привязан к `127.0.0.1`; публикация на Vercel требует настроить `DATABASE_URL` в секретах проекта и подключить внешний PostgreSQL.
- Каталог публичен на чтение. Не вносите туда персональные или конфиденциальные данные.
- Пароли хешируются через `scrypt` с индивидуальной солью. Защищайте доступ к PostgreSQL и резервным копиям.
- Сессии хранятся в PostgreSQL, cookie имеет `HttpOnly; SameSite=Strict` и срок 8 часов; при HTTPS добавляется `Secure`.
- Нет смены или восстановления пароля через интерфейс. Не теряйте пароль администратора; сброс требует отдельной безопасной процедуры.
- Не реализованы: подтверждение почты, загрузка фото, восстановление пароля и изменение роли существующего аккаунта.
- Коэффициент CO₂ и цель — демонстрационные значения, а не экологическое заключение.
- Для публикации в интернете понадобятся HTTPS, защищённое развертывание, резервное копирование, процедура восстановления пароля и дополнительная проверка защиты.

## Частые вопросы

### Почему сайт просит создать администратора?

В подключённой PostgreSQL-базе пока нет аккаунтов. Создайте первого администратора. Если переносите данные старой версии, используйте `npm run migrate:sqlite` до создания аккаунта.

### Почему мастер создания администратора пропал?

В базе уже есть аккаунт. Используйте кнопку «Войти». Не удаляйте базу наугад: там хранятся посадки.

### Какие данные вводить в форме администратора?

Логин: 3–32 символа, латиница, цифры, `.`, `-`, `_`; без пробелов. Пароль: 10–128 символов. Придумайте значения и вводите прямо на сайте; пароль не отправляйте в чат.

### Сохраняются ли вход и записи после перезапуска?

Да. Записи, аккаунты и сессии хранятся в PostgreSQL и не зависят от памяти или диска serverless-инстанса.

### Почему `store.json` не обновляется?

Старая версия могла использовать JSON как источник разовой импорта в SQLite. Текущая версия работает с PostgreSQL; JSON автоматически не импортируется.

### Почему SQLite не отображается в Git?

`.gitignore` исключает SQLite, локальные `.env` и JSON. PostgreSQL-дампы также храните вне репозитория.

### Почему не получается открыть сайт с другого телефона?

Сервер слушает только `127.0.0.1`. Доступ из локальной сети и публичное размещение не настроены.
